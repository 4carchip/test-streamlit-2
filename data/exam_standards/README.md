# ClassMate 과목 매핑 설계 (출제기준 기반 검색 방식)

"이 개념은 정보처리기사 필기에도 나옵니다" 라는 문장을 **AI가 생성하지 않고, 데이터에서 찾아오도록** 만들기 위한 설계와 초기 데이터입니다.

## 1. 왜 생성이 아니라 검색인가

LLM에게 "이 개념이 다른 자격증에도 나오는지" 자유롭게 답하게 하면, 그럴듯하지만 근거 없는 연결을 만들어 냅니다. 학습자는 그 말이 맞는지 확인할 방법이 없고, 심사에서도 "근거가 뭐냐"는 질문에 답할 수 없습니다.

그래서 매핑을 다음과 같이 바꿉니다.

| | 생성 방식 (지양) | 검색 방식 (채택) |
|---|---|---|
| 출력 | LLM이 문장으로 서술 | 출제기준 항목 ID를 조회해 표시 |
| 근거 | 없음 | 공식 출제기준 항목명 + 검토자 |
| 틀렸을 때 | 추적 불가 | 해당 링크 행만 수정 |
| 신뢰 표시 | 불가능 | relation / confidence / verified |

LLM의 역할은 **"교재 문장에서 개념을 뽑아내고, 매핑 후보를 제안하는 것"**까지입니다. 최종 표시는 사람이 확인한(`verified=TRUE`) 데이터만 사용합니다.

## 2. 데이터 구조 (3개 테이블)

### exam_items.csv — 출제기준 항목
각 자격증의 과목·주요항목을 ID로 만든 표입니다. 여기에 없는 항목은 화면에 표시하지 않습니다.

| 컬럼 | 설명 |
|---|---|
| `item_id` | 항목 식별자 (예: `ADSP-1-1`, `GIGI-3-C`) |
| `exam` / `subject_no` / `subject` | 자격증명, 과목 번호, 과목명 |
| `main_topic` / `sub_topic` | 출제기준의 주요항목 / 세부항목 |
| `source` | 어느 문서에서 가져왔는지 |
| `verified` | 공식 문서로 확인했는지 (FALSE면 화면에 쓰지 않음) |

### concepts.csv — 개념 사전
교재·강의에서 다루는 개념 하나가 한 행입니다. `aliases`가 있어야 "DW", "데이터웨어하우스"처럼 다르게 쓴 표현도 같은 개념으로 모입니다.

### links.csv — 개념 ↔ 출제기준 연결
실제 "교차 출제" 정보가 담기는 표입니다.

| 컬럼 | 설명 |
|---|---|
| `relation` | `동일개념` / `부분겹침` / `용어공유` |
| `confidence` | 0~1, 후보 생성 시 모델이 매긴 값 |
| `rationale` | 왜 연결했는지 한 줄 |
| `verified` / `checked_by` / `checked_at` | 사람이 확인했는지, 누가, 언제 |

## 3. 동작 흐름

1. 학습자가 질문하거나, 교재 PDF의 특정 페이지를 보고 있습니다.
2. RAG가 근거 문단을 찾습니다. (기존 파이프라인)
3. 그 문단에서 **개념어를 추출**해 `concepts.csv`의 이름·별칭과 매칭합니다.
4. 매칭된 `concept_id`로 `links.csv`를 조회합니다.
5. `verified=TRUE`인 링크만 화면에 표시합니다.
   - 있으면: "이 개념은 **정보처리기사 필기 3과목 데이터베이스 구축**에서도 다룹니다. (동일개념)"
   - `verified=FALSE`만 있으면: "다른 자격증과 관련이 있을 수 있으나 아직 확인되지 않았습니다."
   - 없으면: 아무 말도 하지 않습니다. **추측해서 말하지 않는 것이 이 설계의 핵심입니다.**

> 표시 문구는 relation에 따라 다르게 씁니다.
> `동일개념` → "~에서도 같은 개념으로 출제됩니다"
> `부분겹침` → "~에서 다른 관점(설계·구현)으로 다룹니다"
> `용어공유` → "용어만 같이 쓰이며 출제 범위는 다릅니다"

## 4. 데이터 구축 절차

| 단계 | 내용 | 담당 |
|---|---|---|
| 1 | 두 시험의 **공식 출제기준** 수집 (ADsP: 한국데이터산업진흥원, 정보처리기사: 큐넷 출제기준 PDF) | 공동 |
| 2 | 출제기준을 `exam_items.csv` 형식으로 입력하고 `verified=TRUE` 표시 | 1명 |
| 3 | 교재 PDF에서 개념 후보를 LLM으로 추출 → `concepts.csv` 초안 | 자동 + 검토 |
| 4 | 개념별로 상대 자격증 항목 후보를 LLM이 제안 → `links.csv`에 `verified=FALSE`로 적재 | 자동 |
| 5 | 사람이 출제기준 원문과 대조해 `verified=TRUE` 또는 행 삭제 | 2명 교차 검토 |

**현재 파일 상태:** ADsP 과목·주요항목은 공식 시험안내에서 확인한 값입니다. 정보처리기사는 **과목명만 확인**되었고, 주요항목 행은 `verified=FALSE`인 자리표시입니다. 큐넷 출제기준 PDF를 받아 반드시 교체하세요. 개념·링크 데이터도 구조를 보여 주기 위한 예시이므로 교재를 보며 다시 채워야 합니다.

## 5. 평가 방법

매핑도 숫자로 평가합니다.

- 팀원이 출제기준을 보고 **정답 매핑 30건**을 수작업으로 만듭니다 (정답셋).
- 시스템이 제안한 매핑과 비교해 **정확도**(제안한 것 중 맞는 비율)와 **재현율**(정답 중 찾아낸 비율)을 계산합니다.
- 같은 질문을 LLM에 자유 생성으로 물었을 때와 비교합니다. 특히 **근거 없이 지어낸 매핑의 수**가 줄어드는지가 핵심 결과입니다. (가설 H8)

## 6. 주의 사항

- 출제기준은 개정됩니다. `exam_items.csv`에 기준 연도를 함께 적고, 개정 시 링크를 재검토하세요.
- 기출문제 원문을 복제해 저장하거나 보여 주지 않습니다. 출제기준의 **항목명 단위**로만 다룹니다.
- 교재 PDF는 사용자가 구매한 개인 자료입니다. 저장소에 올리지 말고, 추출한 텍스트도 사용자 세션 범위에서만 사용하세요.
