# 공부하기 답변 방식: 자료 + AI 설명 (2026-11-18)

## 목표 / Goal
사용자 자료가 요약 노트라 "자료만" 답변이 빈약했다. 질문에 대해 ① AI 모델의 일반 설명과 ② 업로드 자료에 정리된 내용을 **나눠서** 보여준다. 기존 "자료만" 방식도 선택할 수 있게 남긴다.

## 결정과 근거 / Decisions & Why
- **두 칸 분리 + 라벨**: 🤖 AI 설명에는 "일반 지식 · 업로드 자료 근거 없음 · 교차검증 대상 아님"을 표시하고 쪽 번호를 금지한다. 📄 내 자료에서는 글머리표에 [자료 p.쪽]을 단다. 어디까지가 교재 내용인지 헷갈리지 않게 하려는 것이다. 발표에서는 "검증된 내용과 아닌 내용을 구분한다"는 강점으로 쓸 수 있다.
- **LLM 호출 2번(한 번에 받아 나누지 않음)**: 한 번에 받아 표식으로 나누면 모델이 형식을 어길 때 깨진다. 2번 호출하면 교차검증에 📄 부분만 정확히 넘길 수 있다. 비용은 약 2배다(사이드바 안내에 "호출 2번" 명시). 자료 검색 결과가 없으면 📄 호출은 하지 않는다.
- **기본값은 "자료 + AI 설명"** (사용자 결정). **PDF 없이는 질문할 수 없음**: PDF 없이 쓰면 일반 챗봇과 같아져 차별점이 사라진다는 추천을 사용자가 받아들였다.
- **교차검증은 📄 부분에만 적용한다.** AI 일반 설명은 대조할 근거가 없다.
- **교차 출제 안내(출제기준 검색)에는 AI 일반 설명을 넣지 않는다.** 질문과 📄 부분만 쓴다(Copilot 지적 1·4).
- **교차검증 호출이 실패해도 본문 답변은 유지한다**(`crosscheck.safe_verify`, Copilot 지적 3).
- **답변은 HTML 허용 없이 그린다.** Sonnet 1차 구현이 `<small>` 라벨 때문에 답변 전체에 `unsafe_allow_html=True`를 붙였다. 모델 출력의 HTML이 실행될 수 있어서 라벨을 마크다운 기울임체로 바꾸고 되돌렸다.
- 퀴즈·오답노트 문제 생성은 바꾸지 않았다(자료 근거만 사용).

## 검증 / Cross-check
### Copilot 응답 전문
```
1. **[중위험] 교차 출제 안내가 AI 일반 설명까지 포함해 오염됩니다.** `mapping.find(question + "\n" + answer_text)`는 hybrid 모드에서 일반 지식과 자료 요약을 모두 전달하므로, 실제 자료와 무관한 개념도 출제 매핑에 등장할 수 있습니다. **수정:** hybrid에서는 질문과 `grounded`(📄 부분)만 전달하고, grounded 모드에서는 기존처럼 최종 자료 답변만 전달하세요.

2. **[중위험] 프롬프트만으로는 핵심 응답 형식이 강제되지 않습니다.** 일반 설명 모델이 쪽 번호를 생성하거나, 자료 요약 모델이 외부 지식을 추가할 수 있습니다. 요구사항 위반 여부를 서버에서 검증하지 않으므로 프롬프트만 믿으면 안 됩니다. **수정:** AI 일반 설명에서 쪽 번호 패턴을 제거하고, 자료 요약은 검증된 컨텍스트 청크와 견적된 문장만 허용하는 후처리 검사를 추가하세요.

3. **[중위험] 교차검증 실패가 본문 답변 전체를 삭제합니다.** `crosscheck.verify()`가 예외를 던지면 동일한 `try`의 `except`가 이미 생성된 AI 설명과 자료 요약을 대신해 `⚠️ AI 호출에 실패했습니다`로 교체합니다. 교차검증은 부가 기능이므로 본문 답변 성공 여부와 분리해야 합니다. **수정:** 일반 설명·자료 요약 호출과 교차검증 호출을 별도 예외 블록으로 분리하고 검증 실패 시 본문은 유지하세요.

4. **[중위험] 교차 출제 안내가 검색 실패 hybrid 응답에 일반 지식 기반으로 실행됩니다.** 검색 결과가 없으면 `mapping.find()`에 AI 일반 설명과 거절 문구가 함께 전달됩니다. 일반 설명에 등장한 개념은 자료 근거가 없더라도 출제 기준 매핑 후보가 될 수 있습니다. **수정:** 검색 히트가 없으면 hybrid에서도 `meta["mapping"]`을 생략하거나 생성하지 마세요.

5. **[하위험] 신규 테스트가 HTML 차단을 실질적으로 검증하지 않습니다.** `test_compose_hybrid_has_no_html_tags`는 고정값 `g`, `n`만 검사하고 모델이 실제로 생성할 `<...>` 출력을 주입하지 않습니다. **수정:** 일반 설명과 자료 요약에 `<script>`, `<iframe>`, `<b>` 등을 넣는 경우 `st.markdown(..., unsafe_allow_html=False)` 또는 명시적 마크다운 검증이 적용되는지 AppTest로 확인하세요.

6. **[하위험] 검색 히트가 없을 때 hybrid가 요구된 2회 호출을 수행하지 않습니다.** 일반 설명은 1회 호출하고 자료 요약은 호출하지 않아 실제 프로세스가 완전히 hybrid 두 호출 구조가 아닙니다. 의도된 비용 최적화라면 명시가 필요하지만, 사용자 요구가 두 칸을 확정적으로 만들고 두 LLM 호출을 요구했다면 누락입니다. **수정:** 호출 수 계약을 명확히 하거나, 검색 없음에서는 두 번째 호출을 하지 않고 사유를 메타데이터로 표시하세요.

- **PDF 미업로드 시 질문 잠금:** diff상 기존 로직과 PDF 관련 분기가 유지되어 별도 고위험 문제가 보이지 않습니다.
- **퀴즈·오답노트:** 요구사항과 무관한 기존 흐름이 변경되도록 보이지 않으며, 별도 문제는 식별되지 않았습니다.
- **자료만 모드의 본문 근거 동작:** 기존 grounded 프롬프트와 검색 조건을 유지하는 방향이므로 새로 식별되는 근본 문제는 없습니다.

```
### 분류
1. 출제 안내에 AI 일반 설명이 섞임 → **반영함**. `answer.mapping_text`, 테스트 3개.
2. 형식을 프롬프트로만 강제함(일반 설명의 쪽 번호, 자료 요약의 외부 지식) → **보류**. 사유: 정규식 후처리는 정상 문장까지 깎을 위험이 있다. 라벨로 구분하고 📄 부분은 교차검증으로 잡는다.
3. 교차검증 실패 시 본문 전체가 사라짐 → **반영함**. `crosscheck.safe_verify`, 테스트 1개.
4. 자료가 없을 때도 일반 설명 기반으로 출제 안내를 만듦 → **반영함(일부)**. 일반 설명은 빼고 **질문만**으로 찾는다. 안내를 아예 빼라는 제안은 보류했다. 사유: 질문한 개념이 어느 시험에 나오는지는 자료가 없어도 유용하고, 출제기준 데이터는 검증된 공식 데이터다.
5. HTML 테스트가 고정 문자열만 검사함 → **보류**. 사유: 실제 방어는 `unsafe_allow_html`을 쓰지 않는 것(Streamlit 기본 이스케이프)이고, 코드 리뷰로 확인했다.
6. 자료가 없을 때 호출이 1번만 일어남 → **해당 없음**. 사유: 의도한 동작이다(📄에 "찾지 못했습니다" 표시). 이 문서에 명시했다.

## 함정 / Gotchas
- BM25 검색은 조각이 1개뿐인 색인에서 점수가 `MIN_SCORE`(1.0)보다 낮게 나와 "자료 없음"이 된다. 테스트용 색인은 조각을 2개 이상 넣어야 한다.
- 이 저장소의 일부 파일은 CRLF 줄바꿈이라, 셸이나 파이썬의 문자열 치환이 조용히 실패할 수 있다. Edit 도구를 쓰거나 줄바꿈을 확인한다.
- `answer`는 이제 모듈 이름이다. `study.py`에서 답변 문자열 변수는 `answer_text`다.
